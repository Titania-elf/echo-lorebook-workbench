# 回声书台 · Echo Workbench

SillyTavern 1.18.0 的世界书编辑、整书整理和生成前目录调度扩展。打开 **魔法棒 → 回声书台**。普通编辑和确认整理都会保存到原世界书，影响所有使用该书的聊天；调度器只处理本轮扫描副本，不改写世界书。

## 安装

在酒馆扩展安装界面使用 `https://github.com/Titania-elf/echo-lorebook-workbench.git`。本地位置通常是 `public/scripts/extensions/third-party/echo-lorebook-workbench/`，不需要构建或安装 npm 依赖。刷新酒馆后从魔法棒打开工作台；`design/` 里的页面是独立示例，不读取真实资料。

模板按实际安装目录加载。改名后不要保留两个扩展副本。`lorebook-director` 和 `lorebook-director-workbench` 是已有设置、聊天规则和原书元数据的兼容键，仍保持不变；全局拦截器 `lorebookDirectorInterceptor` 也保持兼容。

## 整理一本世界书

1. 在世界书工作台打开书，点 **整理当前世界书**。可整理未挂载或未托管的书；不会自动改变挂载关系。先完成未保存的编辑。
2. 核对书名与当前 API 方案，点 **备份并发送全文**。工作台先核对一份完整的原书备份，再按原书顺序每批最多发送 **10 个完整条目**（含禁用条目），不把长条目切碎或截断，也不发送聊天。后续批次会复用前面已有的分类，不另发合并请求。失败或取消不会写回原书；再次打开整理页可点 **继续整理**，在同一浏览器仅重试未完成或已改动的条目。备份不会删除。
3. 检查预览中的拆分、原词／新词、分类和摘要，可展开查看各子条的对应原文。AI 只建议边界和元数据，程序直接切原文，逐条检查所有片段能按顺序完整拼回。不补写、改写、删减或跨条合并。未拆条目和首个子条保留原 ID，新增 ID 只用于实际切出的其他子条。
4. **确认写回原书**后，工作台重新核对备份和原书版本，把条目、分类与目录一次保存。原书有变化就停止。保存响应不确定时使用 **核对保存结果**，先重读原书，不直接重新提交。

- 绿灯主关键词按各段内容重填，可替换旧普通词，写入酒馆实际触发字段，不只是目录标签。不改变蓝绿灯、向量类型或次关键词条件。含已有正则、互斥、激活时序等可能因拆分改变语义的条目不自动拆分；原有正则保留。
- 目录摘要不会写成额外的世界书条目。目录、分类和拆分来源记录在原书的 `extensions.lorebook-director-workbench` 元数据中。条目列表可按分类筛选、搜索标题／关键词／原文和有效目录摘要。
- 备份是一份单独的世界书，不自动挂载或托管。整理后可以回到同一本书的整理页，点 **预览恢复备份**，再单独确认。恢复会替换当前同名原书；备份之后有要保留的编辑时请先另存。恢复不回收已分配的子条 ID。
- 酒馆没有可用于整书编辑的版本条件写入接口。同一工作台的写入会串行，并在提交前核对最新版本；仍应避免在多个窗口同时编辑一本书。

## 目录调度

1. 在酒馆原生设置挂载要使用的书，然后在回声书台 **调度器**勾选托管书。启用生成前调度并保存。只接管有有效目录、已挂载且已托管的适用书；未整理或目录因编辑过期的书仍按酒馆原生规则触发。
2. 从 **调度器 API 设置**选择跟随主连接、酒馆已有连接或自建 API 方案。整理和调度都经酒馆后端转发，不切换正文连接。跟随主连接或已有连接时，保留酒馆配置的反代和提示词后处理。
   - **跟随酒馆主连接**只要求复用连接参数，辅助模型可以从列表选择或手动填写 ID。留空使用正文模型；指定模型只影响当前方案的世界书整理和调度。
   - 自建方案填写**酒馆服务端可访问**的 OpenAI 兼容基础地址，例如 `http://127.0.0.1:8000/v1`。若酒馆运行在容器或其他机器，`127.0.0.1` 指的是酒馆进程所在环境，而非浏览器所在设备。
   - 需要代理专用的鉴权头或参数时，展开 **本地反代选项**，可填写附加请求头、附加请求参数和排除字段（YAML 或 JSON）。附加头也用于获取模型列表；请求参数与排除字段只用于生成。自建方案的密钥和额外头随当前用户设置保存，获取模型列表不发送世界书正文。
3. 用 **试运行（调用 API）** 查看选择结果，不生成正文或注入。若本轮没有可选绿灯，或固定项已耗尽预算，不为这一轮额外调用辅助模型。

辅助模型只收到近期 AI 回复、最新已发送用户发言、选择限制和适用的绿灯目录卡（ID、书名、标题、分类、关键词、摘要）。它只返回候选 ID 和入选理由，不规划剧情，也不注入隐藏导演提示。目录或请求出问题时不会回退到向辅助模型上传世界书全文。

- 蓝灯默认常驻，固定绿灯优先并受绿灯数量和 Token 上限约束，排除只在成功调度时生效。拆分后旧规则继承到子条，可按子条调整。纯向量条目和非托管书仍由原生处理。
- 程序对入选条目的完整原文计算预算，通过原生世界书构造注入，不把摘要或选择理由作为正文资料。正文预设仍需启用本轮所用的世界书之前／之后位置。构造接纳不等于上游收到原文的回执。
- 调度默认关闭；保存的连接、托管书、绿灯预算和聊天规则继续保留。升级时旧剧情导演模板换为目录选择默认模板，不会继续调用原有导演提示。**提示词管理**可编辑目录选择模板的角色、正文、顺序及宏；整理使用单独的结构化协议。
- 普通回复、重生成、滑动和续写可触发调度；安静生成、代写用户和原生 dry-run 不触发生成前辅助请求。API 失败或无法一致核对原书来源时回退原生，不复用上轮选择。
- **调度历史**在当前浏览器保存请求结果、蓝绿条目标题和失败说明，不额外缓存请求中的世界书全文或聊天。旧记录中已经保存的剧情方案仍可查看；新请求不再生成方案。

## 手动维护

- 工作台可查看酒馆全部世界书。条目页保留新增、编辑、启用开关、手动分类和本聊天固定／排除；仅打开或编辑不会自动挂载或托管。手动修改正文、标题或主关键词后，受影响的目录会标记为过期。
- 新增和拆分使用高水位分配 ID，不复用历史空洞。标准角色书以 `originalData.entries` 镜像时，同步改动的已知字段；不会尝试修复任意外部工具生成的异常结构。
- 支持跟随酒馆、日间、夜间主题。插件沿用酒馆字体，SVG 图标许可见 `assets/`。

## 文件组织

- `index.js`、`workbench.html`、`style.css`：宿主入口、工作台模板、样式入口。
- `src/worldbook/`：原书读写、草稿、分类、备份编排、整书拆分校验和目录元数据。
- `src/workbench/`：工作台、编辑器、设置、整理预览和浏览工具。
- `src/scheduler/`：目录选择、原生注入、提示词和结果说明。
- `src/api/`：辅助 API 连接及传输；`src/history/`：本地历史及呈现。
- `tests/`：逻辑测试；`docs/scheduler-flow-plan.md`：旧版导演方案，留作历史说明。

本次改动未运行针对性测试、全量回归、浏览器检查或真实 API 验证。
