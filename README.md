# 回声书台 · Echo Workbench

适配本地 SillyTavern 1.18.0 的前端扩展：**全部世界书编辑工作台＋生成前剧情导演与世界书调度器**。

- 工作台入口：聊天输入区的 **魔法棒 → 回声书台**，使用酒馆原生菜单样式。
- 调度配置与 API 方案从工作台侧边栏的 **调度器** 和 **调度器 API 设置** 管理。
- 可收起的窄侧边栏与独立功能页，手机横竖屏均铺满可用屏幕、默认收起导航，键盘弹出时跟随可见区域调整；全部文字沿用酒馆主题字体，保留原创 SVG 回声徽记与紫绿配色。
- **工作台手动保存会直接修改原世界书，影响所有使用它的聊天。调度器本身只处理扫描副本，不改写原书。**
- 调度默认关闭，保留原有配置；支持独立 API 方案和跟随酒馆主连接。自建方案的密钥随当前用户设置保存，不切换正文连接，不需要构建或安装 npm 依赖。
- **提示词管理**提供剧情导演与资料统筹、目录概括两套可编辑条目。导演身份与 JSON 输出协议是两个独立 System 条目；可以调整消息身份和顺序、插入本轮资料宏。
- **调度历史**在当前浏览器保存自动调度与手动试运行的模型返回原文、导演方案及其独立采用状态、失败原因与蓝灯／绿灯条目标题。
- 调度器根据最近 AI 回复、最新已发送用户输入、角色约束和世界书全文确定**唯一剧情主方向**，可在设定范围内适度主动推进新事件；正文模型执行导演方案，负责语言与表现。方案使用独立的 **System／深度 0** 注入，不写入可见聊天或原世界书。

## 安装与目录名称

仓库：<https://github.com/Titania-elf/echo-lorebook-workbench>

在酒馆扩展安装界面使用：

```text
https://github.com/Titania-elf/echo-lorebook-workbench.git
```

本地目录名称为 `echo-lorebook-workbench`，标准位置：

```text
public/scripts/extensions/third-party/echo-lorebook-workbench/
```

模板加载按实际安装目录定位，不再把安装路径与旧存储键耦合。改名后只保留新目录，不要同时放置旧目录副本，否则可能重复加载。

### 旧配置兼容

`lorebook-director` 仍作为调度配置、聊天规则、工作集的兼容标识；`lorebook-director-workbench` 的 UI 偏好及原书 ID 水位，以及场景指纹前缀也保持不变。这些不是遗漏的安装路径，不应全局替换或清空，否则可能丢失既有状态。

初始化会把旧目录的插件禁用记录迁移到实际安装目录；拦截器也识别新旧名称。全局 `lorebookDirectorInterceptor` 和原生接入契约继续兼容。目录改名不要求修改任何原世界书、聊天文件或 API 密钥。

原来的辅助连接选择继续保留：旧 `profileId` 会识别为“酒馆已有连接”，空选择会识别为“跟随酒馆主连接”。更新调度或目录设置时会保留自建 API 方案。

## 世界书工作台

刷新酒馆页面后从魔法棒打开，不要继续使用 `design/preview.html` 进行实际编辑：那个页面仍是独立示例草图，不读取真实资料。

### 书库与默认目标

- 从侧边栏进入 **世界书工作台、调度器、调度历史、调度器 API 设置、提示词管理**。侧边栏只负责功能导航，具体操作放在对应页面。
- 世界书工作台按照 **世界书列表 → 条目列表 → 条目编辑** 浏览，不再通过编辑页里的下拉框选书或选条目。
- 书库包含**全部酒馆世界书**，未挂载、未托管的书也能打开和编辑。
- 从聊天打开时，将角色绑定、全局启用、聊天挂载和人设挂载的书集中放在“当前聊天启用”组，其他书放在后面；也可以单独筛选当前启用的书。
- “全局已启用”表示世界书挂载设置，不等于上轮某个条目实际激活。
- 群聊有明确当前角色时参考该角色；没有时从已启用全局书开始，不合并全部群成员调度。
- 选书后，条目列表始终显示当前打开的书。点击 **新增条目** 进入这本书的独立创建页，现有条目的编辑页不放新增入口。
- 切换、查看和编辑不会自动挂载世界书，也不会自动把它交给调度器。
- 全库为空时先通过酒馆原生界面创建或导入一本书，再刷新书库；本期不新增整本书创建／改名／删除／导入导出功能。

### 查看、编辑与保存

- 条目列表直接显示标题、正文摘录、分类和触发信息。**启用开关在每个条目旁边**，修改后直接保存到原书；如果已有未保存草稿，会先让你处理草稿。
- 当前书支持标题、主／次关键词和全文搜索，支持状态与分类筛选；每页 50 条，全部条目均可浏览。
- 编辑页直接显示标题、分类、蓝绿灯／向量触发方式、主要／次要关键词、正文、插入位置、顺序和概率；需要时显示次关键词条件、深度／角色或出口名称。
- 同行的输入框和下拉框采用一致的高度，标题区域单独排列；窄屏上标题独占一行，分类与触发方式并排，避免标题换行推歪控件。
- 不常用的递归、预算和匹配覆盖属性放在“高级属性”面板。长正文在自己的输入框内滚动，底部操作始终可见；“放大正文”可以临时腾出更多编辑空间。
- 未显示或未编辑的原生属性、扩展字段及其他条目取最新原值，不以表单重建整个条目。未知枚举保留原值，nullable 字段不统一压成 0 或 false。
- 编辑页底部提供 **复制正文、删除、放弃修改、保存到原书**。正文和分类修改点击保存才提交。
- **复制正文** 将当前编辑框里的正文复制到剪贴板，包含尚未保存的文字，不创建新条目。
- 新增页可以选择分类和触发方式、填写详细字段，并参考通用正文模板；点击 **创建条目** 才写入原书。尚未创建的草稿不进入调度，空正文不会进入本地调度目录。
- 删除单独确认，影响所有使用原书的聊天；不是“本聊天排除”。异常 ID 的条目只提供原始数据查看，不覆盖写入。
- 返回列表、浏览其他书或切换功能页时保留草稿、编辑位置和设置修改；真正更换编辑条目或关闭工作台时，提示保存、放弃或继续编辑。
- 调度状态刷新不会重建编辑表单。未保存草稿仅在当前页面内存中，刷新、退出浏览器或系统结束页面可能丢失。

### 分类整理

- 唯一固定保留的分类视图是 **常驻**，由原书的蓝灯状态自动识别；禁用的蓝灯条目仍在常驻中。
- 不预设人物、背景、地点等分类。使用条目列表里的 **新增分类**，为当前世界书建立需要的分类；创建条目时也可以新增分类。
- 分类与触发方式各自独立，蓝灯条目仍可指定一个自建分类，也可不指定分类。“其他条目”只是列表分组说明，不是预设分类。
- 分类及状态按钮使用小字号和圆角。分类较多时可横向滑动、用鼠标拖动或滚轮浏览，不显示横向滚动条。
- 分类名称和条目归属保存在原书的 `extensions.lorebook-director-workbench` 元数据中，不写进正文或改变蓝绿灯状态。新增分类单独保存，条目归属随“保存到原书”或“创建条目”一起保存。
- 分类保存响应不确定时保留提交信息，重试前先读取原书，避免重复创建。

### 保存边界

- 新写入层检查 HTTP 与后端 `{ ok:true }`，确认后才更新原生缓存和当前同名原生编辑器，不把 `saveWorldInfo()` 的正常 void 返回当作成功。
- 提交前检查真实目录，避免把已删除／改名的书加载成 dummy 空书后重新创建；按当前书名锁定提交目标。
- 同一工作台内的同书写入串行，读取最新原书并检查修改字段冲突。失败／冲突保留草稿，不自动覆盖或自动重试。
- 网络中断、服务端错误或无法解析保存响应时，结果可能不确定：保留提交身份、暂时锁定字段，重试先读取原书，避免盲目重复新增。直接离开不能撤销已经发出的请求。
- 已发出的写入即使聊天切换也只完成锁定的原书；旧编辑页不能把固定／排除写入新聊天。
- **宿主没有版本号或 CAS，不能保证多标签页原子事务。**原生编辑器有共享防抖和旧快照，其他工具／窗口仍可能整书覆盖；避免同时编辑同一本书。
- 新增／删除会在原书 `extensions.lorebook-director-workbench.uidWatermark` 保存本插件的 ID 水位；标准角色书镜像可同步该记录。水位随条目变化同一 JSON 写入，避免仅靠 UI 防抖导致删除 ID 被本工作台重复使用。
- 不保证其他工具、重新导入或整本书替换遵守该身份记录；手动规则不是权限控制。达到原生 ID 安全分配上限时明确失败，不静默复用历史空洞。
- 含 `originalData.entries` 的角色书对已知字段做 id／uid 兼容同步，以及 disable／enabled 取反；不承诺任意外部格式完整往返或自动修复损坏元数据。

### 主题与素材

- **日间／夜间**：独立配色，原色渐变用于品牌与强调，按钮使用对应深浅变体，正文使用中性表面。
- **跟随酒馆**：继承实际 `--SmartThemeBodyColor`、`--SmartThemeBlurTintColor`、`--SmartThemeBorderColor` 等变量，不用手机系统日夜模式替代。
- 界面偏好独立保存于扩展设置，不经调度设置更新；切主题不会取消辅助模型请求。
- 正式插件的标题、正文、按钮和输入框统一继承酒馆字体，不加载自带圆体或其他字体；日间／夜间主题也只调整配色。
- 日间主题的输入框、下拉框、选项和占位文字使用插件自己的浅色配色。字体仍跟随酒馆主题。
- 列表、正文及操作面板使用 2px 宽的矩形滚动提示，滚动时显示，停止后自动隐藏。
- SVG 图标保留 Lucide／Feather 许可，见 `assets/`。历史示例的字体素材及原授权仍保留，但正式界面不再加载。

## 开始使用调度器

1. 打开角色聊天，按酒馆原生方式挂载世界书（角色、全局、聊天或人设书）。
2. 从回声书台侧边栏进入 **调度器**，选择托管书，设置最近 AI 楼层数、绿灯条目／Token 上限与导演方案 Token 上限，点击 **保存调度设置**。最新已发送用户发言独立读取，不占 AI 楼层数量；同时提供角色描述、性格、场景、用户人设和角色深度提示。蓝灯默认常驻，不占绿灯上限。勾选未挂载的书不会加载到本聊天。
3. 从侧边栏进入 **调度器 API 设置**，选择或新建方案，设置超时时间，点击 **保存 API 设置**：
   - **跟随酒馆主连接**：复用当前模型与路由；当前主 API 必须是聊天补全。
   - **自建 API 方案**：填写独立的 API 地址、密钥和模型，支持 OpenAI 兼容接口；也可以为方案选择跟随主连接。
   - **酒馆已有连接**：使用连接管理器中保存的配置；连接失效时明确报错。
4. 保留正文预设中的 **世界书之前／世界书之后** 与 **聊天历史** 位置。资料仍走前／后位置，导演方案单独使用 **System／深度 0**，不修改预设或原书。
5. 使用 **试运行（调用 API）** 查看导演主方向、节点、收束与参考条目，不发送正文。没有候选绿灯、未托管书或固定条目用满绿灯预算时，仍调用导演 API，根据聊天、角色约束和可用资料构思。
6. 可为绿灯设置“本聊天固定／排除”。**AI 展示概括（调用 API）** 是可选的目录展示功能，全文筛选不依赖它；刷新本地目录也不调用筛选模型。
7. 在调度页开启 **生成前调度** 并保存设置，正常聊天便会触发调度。尚未保存的设置会保留在页面中，保存后才能试选或概括目录。

默认值：绿灯最多 8 条、绿灯预算 1800 tokens、导演方案上限 1000 tokens、最近 3 层 AI 回复、等待上限 60 秒。绿灯数量为 1～30 条、预算为 128～16,000 Token，导演方案上限为 128～4000 Token，AI 读取为 1～30 层，均填写整数。已有保存值继续沿用；新增方案上限采用默认值。

导演方案预算包含固定执行指导、方案文字、标记与消息开销，不占绿灯预算，但仍计入正文总上下文。程序先估算固定开销，将剩余文字预算提供给导演；最终超限时不截断方案，而是说明原因并不采用它。过低的方案上限可能不足以容纳固定指导。

蓝灯常驻全部加入。先排除用户、系统与空白消息，再取最近的有效 AI 楼层；AI 消息不足设置数量时读取现有的全部有效 AI 消息。每层 AI 回复、最新用户发言和参与判断的条目正文完整读取，不用目录摘录或摘要替代。最新用户发言单独提供，不从 AI 数组中反查。

### 新建与管理 API 方案

- 点击 **新增方案**，填写方案名称并选择连接方式。自定义方案填写 API 基础地址（例如 `https://example.com/v1`）、密钥和模型；无需密钥的本地接口可以留空。
- **自动获取模型列表**默认开启。填写或修改地址、密钥后会稍作等待，再通过酒馆后端读取该 API 的模型列表；也可点击 **获取模型列表**手动刷新。
- 模型列表失败、为空或接口不提供列表时，可直接填写 **模型 ID**。获取列表不自动替你选择第一个模型，也不发送聊天或世界书内容。
- 方案中的地址、密钥或选择发生变化时，旧请求结果不会覆盖新方案的列表。关闭工作台会取消尚未完成的列表获取。
- 点击 **保存 API 设置**后，新增、删除、修改和方案切换才生效。点击 **删除方案**需要确认，保存后删除方案及其密钥，调度器恢复跟随主连接。
- 自建方案的密钥以明文保存在当前酒馆用户的扩展设置中。跟随主连接和酒馆已有连接只引用酒馆原来的连接，不复制密钥到方案中。
- API 方案供剧情导演、资料统筹与 AI 目录概括使用。自定义请求使用独立的连接信息，不修改酒馆的主 API 选择或主连接密钥。

### 提示词管理

从侧边栏打开 **提示词管理**，选择 **剧情导演与资料统筹** 或 **目录概括**。导演任务默认有十个条目：导演身份与职责、JSON 输出协议、任务与预算、角色与用户人设约束、最近 AI 消息、旧场景参考、蓝灯资料、固定绿灯、候选绿灯、最新已发送用户发言。身份与输出格式分别独立编辑；目录概括仍为两条独立提示词。

- 默认仅**最新已发送用户发言**使用**用户（User）**；其余所有条目，包括最近 AI 回复和目录概括条目，均使用**系统（System）**。已有保存模板首次加载时迁移一次消息身份并保存，不改变正文、启用状态或排序；之后仍可手动编辑身份。新增条目默认 System。资料条目使用 System 身份也不能修改导演职责或输出协议。
- 兼容“最近聊天”和“最近 AI 消息”两种旧默认文案。完整保留旧七条结构且旧规则未修改时，自动拆分升级、加入角色与用户资料并保存迁移结果；自定义旧规则或已删除的条目不自动覆盖、补全。自定义模板需适配新输入与必填 `replyPlan`，或使用已有的“恢复本任务默认”再保存。
- 选中条目后，可以编辑名称、正文与消息身份：**系统（System）／用户（User）／助手（Assistant）**。
- 条目启用状态统一通过列表中的开关控制。点击 **…** 会直接在该条目内展开操作按钮，再次点击可收起；删除会直接移除草稿条目，保存后生效。拖动条目左侧的抓手调整顺序，松开后更新；也可在抓手上使用上下方向键。启用条目按列表顺序分别组成消息。
- 手机端先展示条目列表，点击条目进入编辑，使用 **返回提示词条目**回到列表；返回时保留未保存的正文和阅读位置。
- 将光标放到正文中，点击文本框右上角的简洁 **插入宏** 图标，从弹出列表选择所需资料。宏插入原光标位置，也可以替换选中的文字。
- 顶部栏中、关闭按钮旁的 **?** 说明每个宏的作用、适用任务和数据格式，也说明模型需要返回的 JSON 结构；滚动正文时仍可打开帮助。
- 点击 **保存提示词** 后，下一次试选、生成前调度或目录概括使用新配置。切换页面保留草稿；关闭工作台时可以保存、放弃或继续编辑。**恢复默认**只替换当前用途的草稿，仍需保存才生效。

辅助请求会关闭连接中可选的消息合并后处理，已有连接仍保留其采样设置和路由。部分原生模型接口会按自身要求转换消息身份。

导演返回必须包含 `selected` 数组与 `replyPlan` 对象。方案包含唯一 `direction`、顺序排列的 1～8 个 `beats`、0～12 个 `constraints`、明确的 `ending` 与 `requiredEntryIds`。依赖 ID 只允许本轮蓝灯、已纳入固定绿灯及 `selected`，程序按 ID 注入原文。`scene` 和 `scope` 仍可省略；场景只能记录已确认事实。目录概括仍只返回 `summaries`，不需要导演方案。

### 调度历史

从侧边栏打开 **调度历史**，默认查看当前聊天，也可以选择全部聊天、记录状态或搜索模型、方案、聊天名称、条目标题、世界书名和错误。电脑上左侧是记录列表，右侧是详情；窄屏点击记录进入详情，使用 **返回记录列表**继续浏览。

- 自动调度与手动试运行创建导演 API 记录，保存模型、方案名称、发起／提交／结束时间与耗时。无候选绿灯的导演调用也记录；重生成、滑动重写、续写各自新增记录。
- 导演方案单独显示主方向、拟议节点、边界、收束与必需资料。方案的等待、试运行、注入、省略及取消状态独立于整体资料采用状态；旧记录没有方案时明确说明，不补造历史计划。暂存注入不等于最终构造接纳，更不等于剧情已经发生。
- 模型返回原文在 JSON 解析前保存，保留完整文字。JSON 不完整、未知 ID 或缺少必要字段时，会显示 **返回无效**和具体原因，原文仍可查看。
- 请求失败、超时、用户取消、聊天或设置变化都会记录原因。接口已返回有效结果而后续未采用时，分别显示 **已返回**与 **未采用原因**；迟到的内容附到原请求，不覆盖新请求或恢复已取消状态。
- 场景参考保存失败会作为记录说明展示，接口和已采用状态保持各自的结果。
- 详情分别展示 **蓝灯条目**和 **绿灯条目**的数量、标题及所属世界书。绿灯包含本轮通过预算与数量限制的手动固定条目和模型入选条目；电脑上两组并列，窄屏上下排列。
- 自动调度采用后，**本次生效条目**以酒馆本轮世界书构造接纳的调度条目为准。手动试选、等待构造或未采用时，明确展示试选结果、计划或已准备条目；构造接纳不代表每条正文已发送到上游模型。
- 标题、书名与 ID 按本次请求的目录保存，后续改名或删除条目不改变历史中的名称。旧记录缺少这些资料时显示 **这条历史未记录条目标题**，无法可靠补回当时的名称。
- 当前浏览器按酒馆服务器与账号分别保存历史，并按聊天文件归档；新分支使用独立归属。刷新后可读取本地记录；目录概括不计入调度历史。
- 默认按最近 **100 条**整理，优先移除最旧的已结束记录，进行中的记录等结束后再参与清理。单条原文不做字符截断。历史独立于场景记忆，清空场景记忆不删除调用记录。
- 页面关闭后没有取得最终结果的旧请求，能确认结束时标记为取消；无法确认时显示 **最终结果未确认**。浏览器存储不可用时，页面会说明记录只能保留在当前页面内存中。

历史页面提供阅读，不增加复制按钮。除模型返回原文，另保存经结构过滤的导演方案、状态、原因与 Token 估算；条目快照仍只保存 ID、标题和书名。不额外保存请求提示词、输入聊天、世界书全文或连接密钥，不将导演计划写入聊天文件或跨设备同步。旧记录缺失的原始返回或方案不能补回。

### 每次生成时会发生什么

1. 酒馆准备好本次聊天文本后，先等待调度。普通发送包含新提交的消息；重生成、滑动与续写使用酒馆为该操作准备的历史。
2. 从酒馆为该操作准备的聊天中读取最近 N 条有效 AI 回复全文，另取最新已发送用户发言全文，并提供角色描述、性格、场景、用户人设和角色深度提示。用户不占 AI 楼层数；试运行使用已发送聊天，不读取输入框草稿。生成使用酒馆已处理的正则、附件文本及推理配置；续写只规划尚未完成的后续。
3. 读取当前已挂载且勾选托管的书，核对已保存版本与原生读取。读取失败、原生漏读或内容不一致会跳过本轮调度，不把错误当成“0 个可用条目”。
4. 已启用且符合角色、生成类型和禁止激活标记的蓝灯默认加入。纯向量条目保留原生处理，蓝灯＋向量的组合按蓝灯处理。
5. 同一次辅助请求构思唯一主方向与配套资料。导演允许适度主动引入有设定依据的新事件，但不编造关键设定、不替用户作决定、不提前泄露角色未知秘密；返回完整绿灯选择及导演方案。
6. 固定绿灯优先，其后优先纳入方案必需的绿灯，再纳入其他选择，各组保留模型顺序。数量或 Token 超限完整跳过，不截断原文。方案另计算独立预算；缺少必需资料或超限时只省略方案，说明原因，保留有效资料选择。
7. 世界书原文仍进入“世界书之前／之后”，导演执行指导单独进入 System／深度 0。正文负责表达，不另行规划主线。构造期间再次确认必需原文与完整方案被保留；不能确认时撤下方案。理由、旧场景和 AI 目录不注入。计划不进入已确认场景记忆，临时注入在构造完成、取消、切换与失败时清理。

启用生成前调度后，每次受支持的正文操作通常多一次导演辅助请求。没有候选、未托管任何书或固定绿灯用满预算时仍构思，不再用“无绿灯可选”跳过 API。未挂载或禁用的书不会因此进入导演资料范围。绿灯入选 0 条不代表没有蓝灯、没有方案或没有 API 调用。

已有连接可能在发送前准备采样预设；如果这一步或请求中途失败、尚未取得有效返回，会显示“已交给酒馆连接，发出情况未确认”，不凭开始等待就断言已向上游发出请求。主动停止正文时显示已取消。

世界书浏览、编辑与保存只走酒馆后端，不调用筛选模型。模型列表获取只发送连接信息。可选的 AI 展示概括每批最多 6 条、合计约 12000 字符，单条超过 10000 字符时保留本地摘录；这些展示限制不用于全文筛选。

## 调度规则

### 托管范围、位置与手动规则

- 托管书选择全局保存，仅当前聊天原生挂载的书参与。原生禁用、角色名称／标签、生成类型和 `@@dont_activate` 等明确限制仍生效；固定不能解除禁用。
- 本轮托管的前置条目进入 **世界书之前**，后置条目进入 **世界书之后**。深度、作者注释、示例或出口等其他位置统一映射到后置；原书的原位置、顺序及其他属性保留。
- 成功调度的蓝灯和入选绿灯直接进入原生世界书构造集合，不再通过关键词、概率、原生世界书预算或互斥组重筛。未托管书与纯向量条目继续原生处理。
- 正文预设仍决定资料前后标记的实际位置，酒馆仍处理正则、格式化与正文总上下文。需要的资料标记或聊天历史已关闭／不适用于本次生成时，明确跳过并提示，不自动改预设。导演方案单独使用深度 0，位置接近本轮输入，但不是模型提供的数值权重开关。
- 固定／排除只控制绿灯，保存在本聊天元数据，直到手动解除。超限的固定绿灯会显示未纳入理由。
- 旧蓝灯固定／排除规则保留但暂不生效，切回绿灯后仍可使用；也可以点击 **解除旧规则**。禁用或不再挂载的条目也能解除旧规则。
- 清空场景记忆只清快照，不清手动规则。

### 场景参考与结果

- 每轮重新判断，不自动沿用上轮绿灯。`selected` 必须是本轮完整选择，`reason` 必填；`scene` 和 `scope` 可选。
- `scene` 仅记录已确认情况；`scope="scene"` 的绿灯可保留为下轮参考，仍须重新入选。未填写 scope 时按本轮临时资料处理。`replyPlan` 与场景快照分离，只保存在结果与本地调用历史，下轮以实际正文重新构思，不假定上轮计划已经实现。
- 最近 16 个有效快照继续保存于聊天元数据，按消息前缀指纹区分编辑、重生成与滑动分支。
- 在提示词构造完成后，只将世界书构造集合接纳的场景绿灯写回参考快照。保存原书会取消旧调度，已有快照和手动规则不会因升级而清空。
- 结果分别列出完整读取的 AI 楼层、蓝灯、绿灯候选与入选、绿灯预算、前后位置、API 提交情况及构造接纳情况，可以点击打开对应原条目。
- **构造接纳不是上游收到全文的证明**：正则可能清空内容，正文总上下文、预设格式化或其他插件还可能改变最终请求；本插件没有上游接收回执。

### 全文、宏与试选

- 最近 N 层 AI 回复、最新用户发言和参与判断的条目正文不设本地字符裁剪，不用目录摘录或 AI 摘要代替。上游模型的上下文上限仍适用；超出时明确失败并跳过。
- 筛选模型看到条目保存的全文；只有本轮实际纳入的原文才做酒馆宏替换，交给原生构造处理世界书正则。
- 绿灯 Token 上限是对未展开宏的条目文本的估算，避免为了预筛而执行未选条目的变量或随机宏。它不是最终提示词的精确 Token 数。
- 试选不注入正文、不更新场景记忆，也不展开条目宏。它展示本轮计划，生成时才使用酒馆正式准备的聊天和前后标记。
- AI 概括和本地摘录只是工作台的展示内容，保存正文不会自动调用概括 API。

### 失败与原生恢复

- API 错误、超时、无效 JSON、缺少导演方案、未知／未入选依赖 ID、读取错误或原书变化时，丢弃本轮调度并继续原生生成，不复用上轮资料或方案。
- 合法返回中的方案若超出独立预算、必需资料未纳入，或构造中无法确认完整原文与方案被保留，只撤下导演方案并说明原因，保留有效的资料调度，由正文自行构思。必需原文被正则或格式化改写时采用保守判断；不为检查依赖而重复执行可能有副作用的世界书正则或宏。
- 酒馆页面顶部显示失败原因和已跳过说明，工作台关闭时也能看到。通知自动消失，可手动关闭，不要求确认。
- 若尚未接管扫描，直接放行原生路径；若原生扫描已经拿到临时副本，撤销本轮注入和临时覆盖，按原来的聊天重新完成一次原生扫描，包括已达到递归次数上限的情况。
- 原生世界书构造完成后，辅助筛选已经结束，取消辅助请求按钮随之收起。此后编辑原书或修改规则从下一次生成生效，本轮仍使用已经准备好的资料；主动停止正文仍由酒馆停止按钮处理。
- 回退后的手动排除不限制原生触发。调度器不是剧透权限控制；需要禁止发送的条目仍应使用禁用／挂载等明确条件。
- 普通回复、重生成、滑动、续写运行调度；安静生成、代写用户和原生 dry-run 提示预览不调用辅助筛选模型。
- 成功调度不使用原生黏性／冷却决定蓝绿条目；旧计时数据保留供原生回退使用，不保证托管期间的计时连续。
- 原生世界书事件没有请求 ID，本实现使用本轮标识和同一扫描数组跟踪副本，检测到变化或重复读取时放弃结果。多个插件同时直接构造世界书仍不能保证严格隔离。

## 文件组织

- `index.js`：宿主事件、拦截器、魔法棒及初始化。
- `core.js` / `director.js` / `transport.js`：最新用户输入、资料分配、导演与资料调度生命周期及辅助请求路由。
- `reply-plan.js`：导演方案结构校验、必需资料依赖与隐藏执行指导格式；生成的文字不执行宿主宏。
- `scheduler-native.js`：本轮条目副本、扫描归属、前后注入与撤销；`scheduler-report.js`：蓝绿数量、API 状态与结果文案。
- `scheduler-notice.js` / `styles/notices.css`：独立于工作台的顶部失败通知。
- `scheduler-history.js` / `scheduler-history-store.js` / `scheduler-history-ui.js`：请求来源与失败说明、本地持久历史及记录查看页面。
- `api-connections.js`：独立 API 参数、地址整理、模型列表获取与取消。
- `prompt-templates.js`：默认提示词条目、消息身份、资料宏、配置整理及辅助请求消息组装。
