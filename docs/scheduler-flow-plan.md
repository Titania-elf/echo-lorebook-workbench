# 剧情导演与全文资料调度方案（历史）

> 本文记录旧版方案。当前版本已移除剧情规划，改用世界书整理后的目录调度；以 README 的使用说明为准。

本方案落实已确定的职责：调度器担任幕后剧情导演兼设定统筹，完整决定下一次回复的唯一主方向、节点顺序和收束；正文模型负责语言、对白、动作、心理描写及表现节奏，不再另开剧情分支。导演可以在既有设定范围内适度主动推进、引入有因果依据的新事件，但不能编造关键设定、替用户作决定或提前揭露角色未知的秘密。

## 本轮输入与辅助请求

1. 沿用生成前拦截入口，等待导演完成后继续原来的正文请求，不另起正文生成。
2. 读取酒馆为该操作准备的最近 N 层有效 AI 回复全文，另取最新已发送用户发言全文；最新用户发言不占 AI 楼层数，不读取输入框草稿。普通回复、重生成、滑动与续写使用各自的实际上下文，续写只规划未完成的后续。
3. 提供当前角色名称、描述、性格、场景、用户人设及角色深度提示。角色约束只作为资料，不能改写导演任务或输出协议。
4. 仅将已挂载、勾选托管且符合启用及明确限制的世界书条目交给导演。读取已保存全文并核对原生来源。蓝灯全部纳入；固定绿灯先通过数量与预算限制；候选绿灯排除固定及手动排除项。纯向量条目保持原生处理。
5. 同一次辅助请求完成导演构思与绿灯选择。无候选、固定绿灯用满限制、无托管条目时仍调用导演；无书时只按聊天与角色约束规划，不读取未挂载书或补造设定。

## 提示词条目与返回协议

- `selector` 用途 ID 保持不变，显示为“剧情导演与资料统筹”；目录概括独立保留。
- 仅“最新已发送用户发言”默认使用 User，其余条目（含最近 AI 回复与目录概括）默认全部 System。已有模板做一次消息身份迁移并保存版本标记，只改变 role，不改变正文、开关与顺序；此后仍允许手动编辑身份，不在每次整理时重置。
- “导演身份与职责”和“JSON 输出协议”为两个独立可编辑 System 条目，身份中不再混入完整响应示例。任务预算、角色上下文、AI 回复、旧场景、蓝灯、固定绿灯、候选绿灯与最新用户发言另列。
- 识别完整保留的“最近聊天”及“最近 AI 消息”两种旧默认文案并原位升级，保留自定义资料、名称、开关和相对顺序；消息身份按上述独立的一次性迁移规则处理。初始化时保存识别到的迁移结果；旧默认聊天说明同步更新为最近 AI 回复。旧规则已改写、关闭、变更身份或旧条目被删除时不自动覆盖；自定义模板需手动适配新输入与协议。新版被删除或关闭的条目不在常规整理中补回。
- 导演返回 `selected` 与必填 `replyPlan`；`scene` 仍可省略，只记录已确认事实。
- `selected` 是完整候选绿灯选择，每项有原始 ID、理由及可选的 `turn`／`scene` 范围。
- `replyPlan` 包含：唯一 `direction`、按执行顺序排列的 1～8 个 `beats`、0～12 个 `constraints`、明确的 `ending`、`requiredEntryIds` 数组。
- 必需依赖 ID 只允许本轮蓝灯、已纳入固定绿灯与 `selected`。依赖候选原文必须先选入，不能以转述条目替代参考原文或绕过预算。

## 预算与依赖

1. 绿灯数量／Token 上限不变，蓝灯不消耗这些上限。分配顺序为固定绿灯、导演必需绿灯、其他选择；各组保持模型顺序。超限条目完整跳过，不截断原文。
2. 新增独立 `replyPlanTokenBudget`，默认 1000，范围 128～4000，包含执行指导、方案文字、标记与消息估算开销；仍计入正文总上下文。
3. 请求前估算固定指导，给出 `replyPlanContentTokenBudget` 作为方案文字可用预算。返回后计算整段注入，超限时不截断，而是省略方案并说明原因。
4. 必需条目未通过绿灯预算／数量限制时省略方案，保留合法资料选择。结构错误、未知或未入选的依赖 ID 则使本轮返回无效，走原生回退。
5. 扫描接纳后及正文提示词准备阶段再次确认依赖。必需原文未完整保留（包括被总预算、正则或格式化改变而无法确认）时撤下方案。不重复执行世界书正则或宏作为检查，以免产生额外副作用。

## 酒馆注入与生命周期

- 蓝灯及入选绿灯原文副本继续走“世界书之前／之后”；其他原位置本轮映射到后置，不修改原书属性、预设或共享缓存。
- 导演执行指导使用独立扩展提示词键、System 身份、IN_CHAT／深度 0、关闭世界书扫描参与。仅注入执行指导，不注入选择理由、原始 JSON、依赖 ID 或目录摘要，不写入可见聊天。
- 每轮使用独立标识包裹方案，避免清理时误删其他扩展提示词；AI 生成方案中的宏字符串按字面处理，不执行宿主宏。
- 托管条目仍在来源事件中临时遮罩、扫描完成事件中按本轮允许列表接管。没有托管条目时不遮罩来源；宿主在零条目时会提前返回，因此在已确认的来源读取后准备仅导演方案的注入。
- 正文构造中确认方案和依赖原文仍完整保留；不能确认时清理临时提示词与本轮生成数据中的对应标记段，降为省略并通知。
- 停止、聊天／设置改变、下一轮生成、失败回退及构造完成时清理本轮临时注入，不复用旧方案。已提交构造的资料遵循原有“修改从下一轮生效”边界。
- `scene` 和场景绿灯仍写入已确认参考快照。导演未来安排只保存在结果与浏览器本地调用历史，不写入场景记忆；下轮以实际正文重新判断。

## 结果与历史

- 调度结果与历史分别展示主方向、拟议节点、约束、收束、依赖标题和方案 Token 数。
- 方案状态独立为等待、试运行、注入、省略或取消，不与世界书整体采用状态混同；方案未采用仍可有有效的资料调度。
- 注入仅说明本轮提示词构造状态，不表示上游已经接收，也不表示计划事件已经发生。
- 历史保留原始返回及经形状过滤、深克隆的方案展示字段，不额外持久保存输入聊天、世界书全文、提示词请求或凭据。旧记录没有方案时明确说明，不补造内容；迟到返回不能复活取消／省略方案。
